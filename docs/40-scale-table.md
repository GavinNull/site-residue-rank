## 5. Rose 自己的标度：对 docs/38 建议的**评估**（不是执行）

### 5.1 三条理由逐条检验

**理由 1「四个场景的区间全部重叠，20 个氨基酸分辨不了 0.43 与 0.80」——
作为理由不成立。**

区间重叠用的是**两条标度各自的边际区间**。但两条标度是在**同一 20 个残基**上
算的，差值是配对量：对同一次重抽同时算两条标度、再取差，区间窄得多。
配对 bootstrap（同一次重抽，4000 次，seed 11）：

| 对比 | 口径 A：Δr² [95%] | 口径 D：Δr² [95%] |
|---|---|---|
| **`ROSG850101` − `RADA880106`（在用）** | **+0.389 [+0.172, +0.620] 不含 0** | **+0.367 [+0.136, +0.612] 不含 0** |
| `ROSG850101` − β 折叠倾向 | +0.071 [−0.152, +0.313] 含 0 | +0.178 [−0.077, +0.442] 含 0 |
| `ROSG850101` − π 辛醇 | +0.167 [−0.058, +0.444] 含 0 | +0.272 [+0.039, +0.536] **不含 0** |
| β 折叠倾向 − Kyte–Doolittle | +0.373 [+0.057, +0.682] **不含 0** | +0.382 [+0.064, +0.682] **不含 0** |
| 可及表面积 − Kyte–Doolittle | +0.055 [−0.409, +0.514] 含 0 | +0.194 [−0.263, +0.616] 含 0 |
| β 折叠倾向 − 可及表面积 | +0.318 [−0.049, +0.621] 含 0 | +0.189 [−0.204, +0.525] 含 0 |

`facts:` **`ROSG850101` 比在用的 `RADA880106` 好，在两个口径下都是可分辨的**
（配对区间不含 0）。docs/38 的「全部重叠」是边际区间的产物，
换成配对口径后结论反了。
`facts:` 同一张表也给出一条对正文**有利**的结果：
**β 折叠倾向 > Kyte–Doolittle 在两个口径下都可分辨**
（这比边际区间允许说的强，边际区间在口径 A 下是重叠的：[0.507,0.857] vs [0.090,0.586]）。
`facts:` 而**表内其余所有相邻对比都含 0**。

`assessment:` 边际区间重叠在这类配对比较里是**欠功效**的判据，
与 D-014 同形（选择程序欠功效，看起来像「无结构」）。
本仓库 §5 写的是「比区间重叠与否」，没有指定配对与否；
建议把「同一支撑集上的两条标度之比较一律用配对区间」写成口径。
（confidence: 中高；basis: 上表；caveat: n = 20 上 r² 之差的百分位 bootstrap
是近似的，且**不含 `u` 的不确定性**——而 §3 显示后者更大，
留一会把 `ROSG850101` 推到 0.480–0.831、把 `RADA880106` 推到 0.113–0.615，
两者**仍不重叠于点估计层面**，但这一点未做配对化。）

**理由 2「加标度要把置换天花板重算」——事实成立，但量级可忽略。**

§2 的表给了数：池 21 → 23，max|r| 的 p95 从 **0.621 → 0.625**
（r² 0.386 → 0.391）。即加两条 Rose 使天花板动 **0.004**。
`assessment:` 这条理由在原则上对（天花板必须按实际候选量算），
但它不能承担「所以不加」的结论——**0.004 不改变任何一行的判读**。
（confidence: 高；basis: §2 表，同一置换口径、同一 nsim。）

**理由 3「先看到它最高再写进最佳单条表，是事后挑选」——这条成立，
而且是三条里唯一成立的。** 但它有方向性，见 §5.2。

## 6. 门禁加固

### 6.1 为什么不塞进 `make_figures.py`

`make_figures.py` 的 `EXPECT` 是**图的** 10 个汇总量；§3.3 的表**没有图**，
它的契约（「每张图在画之前核对自己的汇总量」）对这张表无处挂靠。
更要紧的是：在人类按 §7 应用替换文本之前，正文里的表值**是已知错的**，
把它加进 `EXPECT` 会让那条一直绿的门禁立刻变红并长期红着，
而一条长期红的门禁的下一步总是放宽 `TOL`。

所以**另立一条门禁**：`analysis/check_scale_table.py`。
并在 `make_figures.py` 的 docstring 里加了一段「本门禁覆盖什么、不覆盖什么」，
直接写明它的 PASS **不覆盖** §3.3 的表、那张表由谁把门
——这是 D-077 配套发现（「一个检查器的 PASS 不能被当成它没覆盖的东西
也被检查过的证据」）的机械化。**`make_figures.py` 的断言一条都没动。**

### 6.2 新门禁做什么

一条命令：`python3 analysis/check_scale_table.py`

1. **强制自检**（§4 的正向 6 条 + 反向 5 条），不过就 `return 2`，不出任何数字；
2. **就地重算共识轴**（不是读缓存就用），与 `cache/gate_consequences.json`
   比对 λ₁ 与 \|cos\|，容差 1e-9；
3. 对两个口径分别重算五行的 r / r² / n / bootstrap 区间，
   与写定值比（`TOL = 0.0015`，与 `make_figures.py` 同容差）；
4. **解析 `docs/35` §3.3 与 `docs/30` §2 的表**，逐行比对
   8 成员口径，并检查标签/行序是否对得上、警示块是否还在；
5. 任何不一致 → 列出每一处 → **exit 1**。

`--selftest` 只跑自检；`--no-docs` 只跑「表值 ↔ 缓存」那一半。
