# 设计：为什么是这个架构

## 核心判断：缺的不是候选，是判别集

物理有机化学里能写出来的候选量（静电势矩、方向性氢键项、去溶剂化惩罚、
局部软硬度、电荷转移/极化分解、frontier orbital overlap）加上文献里的
打分函数，几十个是轻松的。生成几百个也不难。

问题是生成完之后无法分辨哪个是真信号、哪个是在一个本来信息量就不大的
集合上拟合出来的运气。**所以系统重心压在判别层，不在生成层。**

## 两部分切分

### 第一部分：判别集 + 盲测格式
唯一不可替代的资产。标签物理隔离是这部分的**核心设计**，不是细节。
见 `docs/02-pair-criteria.md`、`CLAUDE.md §1`。

### 第二部分 A：盲预测与因子归因
不是一上来定义标量、算数值、拟合排序，而是对每一对做物理有机层面的论证，
从几百条论证里看什么因子反复起决定作用，再凝练成代理量。

这个路线在学科史上有先例：Hammett 方程不是拟合出来的，是大量个案论证
被压缩后的产物；Taft 的空间参数、Winstein 的溶剂离子化能力标度同一模式。
以前每步都要人做，现在可以并行几百条。

产出不是公式，是**因子-情形的有效性地图** + 校准曲线。见 `docs/04-blind-protocol.md`。

### 第二部分 B：把存活因子实例化为可微量
推理产出的是自然语言论证，不是可微标量，而"可微"是硬约束。
这一步是物理和工程，不是推理。好处是搜索空间被砍掉九成以上——
不再盲搜几十个候选，而是知道只有两三个因子值得做，以及各自的适用情形。

**意外收获**：有效性地图本身决定代理量该不该是单一标量。
若不同因子在不同情形下主导，一个标量在物理上就不可能同时排好所有对，
正确形态可能是**带门控的几项之和**。这个结论靠纯数值搜索很难得出，
靠推理层的分层统计直接看得见。

## 尺度决定：全程不碰完整蛋白

坚持在全蛋白 + 显式水 + 采样的层面做任何事，算力需求立刻上去。
但这个项目允许不这么做——要的量本来就是局域的。

**片段截断**：配体 + 第一壳层接触残基，侧链截到 Cβ/Cγ，加氢封端，冻住骨架。
通常几十到一两百原子，xtb 级别在笔记本上秒级到分钟级。
几百个对 × 20 个扰动构象，一晚上跑完是现实的。

这不是妥协——若声称差异来自核心残基，就应该能在核心残基尺度上算出来。
若必须全蛋白才能复现差异，**假设本身就错了**。所以截断是一个额外检验。

## 已知的天花板，正面处理

片段截断 + 隐式溶剂抓不住结构水：隐式模型对"这个位点有没有一个结构水"
完全无感。而残基身份改变最直接的后果往往就是改变口袋结构水的位置与数量，
一个水分子进出常值 1–2 kcal/mol，足以翻转排序。

**所有便宜且可微的量，描述的几乎都是焓和静电。** 要找的那个标量，
很可能在物理上触不到真正的决定项。

这意味着存在真实失败模式：代理量做到 0.5 相关，剩下的 0.5 不是方法不够好，
是被熵占住了，再搜函数也上不去。

**处理方式不是回避**：`pairs/*.yaml` 的 `water` 字段标注是否涉及结构水变化，
分组报告。若"无水变化"组明显更好，同时得到了方法适用域和论文里最诚实、
最有说服力的那张图。若两组差不多，说明水没想象的那么重要，可以放心往下走。

## 可微性与判别力的内在张力

真正能区分两个口袋的事件常常是离散的：质子转移发生与否、侧链是否翻转、
一个水分子进还是出。这些是开关，不是连续函数。要求可微等于要求代理量在
这些开关附近光滑，而光滑化的代价就是抹掉判别力。

**这不是工程难题，是任务内在的帕累托前沿。** 防护规则写在 `CLAUDE.md §7`。

## 成本结构

判断密集型，不是计算密集型——前提是尺度从一开始定在片段。

| 环节 | 开销 |
|---|---|
| 判别集构造、失败归因、盲预测 | 零算力，纯判断 |
| 探针扫描 | xtb 秒级，关键点小基组 DFT 校准，单机 |
| 基线墙 | docking / MM-GBSA，CPU，几百体系小时量级 |
| 排序评估、bootstrap、对照 | 不值一提 |
| 可微内层 | 若用解析梯度：零训练。若训神经近似：单卡可做 |

可微内层优先走**解析梯度**路线（半经验量本身就有），只在速度确实不够时
才去训网络。这是人类决策点之一。

唯一真正要花钱的是最后的湿实验验证，那个阶段才需要找合作者。

## 两个换不来的东西

1. **实验数据造不出来。** 整个闭环的地基是文献里的 ΔΔG，只能去读、筛、
   判断可比性。这恰好是不耗算力而耗判断的部分，也是本项目的瓶颈。
2. **省算力会压低天花板。** 见上文「已知的天花板」。
