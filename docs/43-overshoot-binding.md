# binding 矩阵的秩 2 是不是定秩程序「高 SNR 过冲」的产物（2026-10-16）

> 本文档回答：docs/42 §3.1 在折叠侧量出、`rank_core.selfcheck` C6b 早已记录、docs/41 §6 写明「没有排除」的那个方向——
> **真秩 1 的矩阵在 binding 矩阵自己的信噪比下，会不会被头条程序报成秩 2。**
> 预先登记在先（哈希锁），双向 harness 在先，三个校正候选在先于任何真实矩阵上的使用。
> **本文档不修改 docs/12、15、16、27、30、32、35、41、42。** 其中一处：我在第一个矩阵的结果出来后发现预先登记的「相容点」定义不能区分路径上的点，

## 1. 先回答：这个方向以前跑过没有

**工具侧的发现（不是数据的错）**：

1. **G2 第一次没过**。wild 噪声直接用 ±d/2，合成重复差的 RMS 比真实 SD 大 3.9%；原因是两次重复之间有**系统偏移**（d 的均值 ≠ 0，库间批次差）。它对每个格子是同一常数，被主效应吸收，不是噪声。改为先去均值再翻符号，之后 14 个矩阵上相对差 ≤ 0.07%。这是实现细节，不改变判决规则。
2. **`rep_noise` 的 √2。** docs/12 §2 与 `censor_recheck.attach_snr` 的重复噪声是**单重复**噪声（SD(d)/√2）；而矩阵每格是**两重复均值**，格子噪声是 SD(d)/2。docs/12 的「信噪比」因此偏低 √2。本文用格子噪声。
3. **SD 对重尾敏感。** S1 deer 的 σ_meas 用 SD 为 0.217，稳健版（1.4826·MAD）为 0.124（`cache/overshoot_noise.json`）。我用 SD（预先登记），更保守地放大了噪声下界，即**对「过冲存在」不利的方向**。

**局限**：
1. σ_meas 是下界；两次重复共享的系统误差看不见。
2. 合成噪声默认各向同性高斯（wild 变体只在 p1 做）；合成缺失与数值无关，真实缺失是信息性的；值域截断是对截尾的温和替代（最高 22%），CR9114 的滴定窗外非线性压缩（4.2%）没有复现。

6. 「过冲」的诊断只覆盖 CV 误差的 argmin；它不回答成分 2 的物理身份。
